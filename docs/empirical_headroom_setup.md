This note describes the implemented first-pass empirical headroom suite.

The active pilot includes:

- `Oracle 0`
- `Marginal counterfactuals`
- `Missed-opportunity accounting`

Deferred for later:

- `Constrained replay`

## Execution Mode

The pilot is `single-node` and `decode-minimized`:

- `max_tokens = 1`
- request-local measurement
- prefill latency is primary
- `TTFT` is secondary

This is intentionally simpler than full PD-disaggregated serving. The goal is to get trustworthy request-local headroom numbers first.

## What Oracle 0 Measures

For each request:

1. clear backend cache state
2. preload all reusable objects for that request
3. run the target request
4. measure:
   - wall time
   - backend-exposed prefill time when available
   - `num_cached_tokens`

This is the optimistic upper bound.

## What Marginal Counterfactuals Measure

For each request:

1. run a natural sequential baseline replay over the workload bundle
2. for each selected reusable object:
   - rebuild the same request-history prefix
   - preload one extra object
   - rerun the target request
3. compute:
   - `marginal_gain_ms = baseline_prefill_or_wall - counterfactual_prefill_or_wall`

This measures per-object recoverable value without a constrained oracle.

## What Missed-Opportunity Accounting Measures

This stage now runs as an analysis pass over the first two studies.

Inputs:

- `oracle0_measurements.jsonl`
- `baseline_replay_measurements.jsonl`
- `marginal_counterfactuals.jsonl`
- the workload bundle manifest

Outputs:

- `missed_opportunities.jsonl`
- `request_gap_summary.jsonl`
- `cause_breakdown.csv`
- `cause_by_object_type.csv`
- `summary.json`

The current implementation is intentionally heuristic. It is designed to turn the Oracle 0 and marginal raw numbers into a first-pass cause breakdown before we invest in stricter attribution logic.

## Nsight Systems

The pilot integrates NVTX and optional `nsys` wrapping.

Collected ranges:

- cache clear
- history replay
- preload
- counterfactual preload
- target request

Sampled `.nsys-rep` outputs are produced when the runner profile flags are non-zero.

## Primary Metrics

- per-request prefill latency
- mean / median / p95 prefill latency
- total prefill latency across the workload
- `TTFT`
- `num_cached_tokens`
- marginal gain per reusable object

## Next Step After the Pilot

If the pilot shows clear headroom:

2. add richer Nsight-derived transfer diagnostics
